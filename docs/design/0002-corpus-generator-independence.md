# 0002 — The corpus generator is not a writer

Status: **normative for this repository**.

## The rule

The conformance corpus is produced by `cargo xtask codegen`, from
`docs/spec/format.yaml` and the fixture descriptions it declares.

The code that emits corpus bytes MUST share nothing with the archive writer:

- **No code.** `xtask` MUST NOT depend on `diavolo-format`, `diavolo-index`,
  `diavolo-ext4` or `diavolo-cli`. The dependency points the other way. The format
  crate includes constants that `xtask` generated, and the tests read files that
  `xtask` emitted.
- **No filesystem knowledge.** No inode walk, no `libext2fs`, no reading of any
  directory tree. Every inode, dirent, extent, xattr and heap string in a fixture is
  written out literally in the fixture description.
- **No compression library.** zstd fixtures are hand-assembled `Raw_Block` and
  `RLE_Block` frames (0001 D6).
- **No layout knowledge in code.** Offsets, sizes and field types come from the layout
  tables in `format.yaml`. The assembler is an interpreter over those tables. It
  places literal field values at the offsets the tables state, and computes only:
  - the digests the spec says are digests;
  - the lengths and counts the spec says are derived;
  - nothing else.

## Why

cdda2img's finding #5 (brief PART 7): every test built its input with the current
writer and checked it with the current reader. A layout change applied consistently
to both passed every test, and silently orphaned every existing file.

If the corpus came from the writer, Diavolo would reproduce that exactly, with a
generator step in the middle.

The assembler **is** a second encoder, and that is the point. It is independent of
the writer, and simple enough to review line by line. What it encodes comes from the
tables, not from a programmer's understanding of the tables.

## Broken siblings

Each broken fixture is a golden fixture plus **one** mutation from a closed
vocabulary. For example:

- set a field;
- corrupt a byte without resealing;
- truncate;
- append.

After the mutation, the assembler **re-seals everything except what the rule under
test covers**. The sibling therefore violates exactly one rule, and the reader must
reject it naming that rule. A sibling that violates two rules at once cannot tell a
missing check from a misattributed one.

If a new fixture needs a mutation the vocabulary cannot express, extend the
vocabulary deliberately, as a table entry. "If your spec vocabulary needs a real
compiler, the analysis is not finished" (brief PART 7).

## What is committed

For every fixture, all generated by `xtask` and all covered by the CI diff gate:

| File | Contents |
|---|---|
| `corpus/golden/<name>.dvl` or `corpus/broken/<name>.dvl` | the bytes |
| `<name>.hex` | an annotated hex rendering, one table field per line, so a byte-level change is reviewable in a normal diff |
| `<name>.expect` (goldens) | the logical content the reader must produce: paths, modes, sizes, digests. Rendered from the fixture description, **not** from the bytes |

For a broken sibling, the rule id the reader must reject it with is recorded in the
generated manifest, `docs/generated/corpus.md`.

## Changing a golden is an act

A golden's bytes change only when the format version is bumped. The regeneration that
rewrites a golden runs only through an explicitly `#[ignore]`d test, so a changed
golden can never be a side effect (brief PART 7).
